# 财资云自动填充插件

本文为 1.0 单站点版本的历史记录。当前多网站版本设计见 [design-v2.md](design-v2.md)。

目标：在 Chrome 打开 `https://toc.icbc.com.cn/login.html#/login` 时，填写用户在插件内保存的一套默认企业编号、账号、密码。

## 实现范围

- 原生 Manifest V3，无构建步骤、无外部依赖、无远程服务。
- 中文弹窗负责保存、修改、清除本地设置，以及手动填写当前登录页。
- 默认启用自动填写；用户可以关闭自动填写并保留手动填写功能。
- 配置仅保存在当前 Chrome 配置文件的 `chrome.storage.local`。密码不写入源码、页面存储或日志，不通过 Chrome 同步服务同步。
- 内容脚本运行在 Chrome 的扩展隔离环境，在填写前检查当前地址与顶层页面，再读取本地配置。网页自身的 JavaScript 不能访问本扩展存储。
- 不使用后台 Service Worker，避免为这三个输入框引入后台启动和凭据转发环节。
- 仅匹配指定 HTTPS 主机、`/login.html` 路径和登录路由。验证码、短信发送、登录提交不属于自动化范围。

## 页面适配证据（2026-10-09）

- Vue 2 / Element UI，企业编号与用户名是普通输入框，placeholder 分别为“请输入企业编号”“请输入用户名”。
- 企业编号 maxlength 为 8，没有仅数字限制；页面可能预填上次企业编号。
- 密码位于 `.ComPasswordInput` 内，placeholder 为“请输入登录密码”；初始 type 是 text。
- 密码组件在冒泡 input 事件中维护真实密码，将 DOM 值更新为星号；输入时需要把光标放到字符串末尾。
- 重填密码先清空并触发 input，等待页面更新，再设置新密码并触发 input。密码不连续同步派发 change，以免嵌套组件把星号显示改回明文。
- 登录方式切换会重建账号、密码节点，企业编号可能被复用；用密码节点识别一次填写的生命周期。

## 自动填写规则

- 等待三个可见、可编辑的输入框出现，支持异步渲染和 hash 路由返回。
- 每个密码节点只自动填写一次；用户开始编辑后停止自动改写这组输入框。
- 账号和密码都为空时，用默认企业编号替换网站记住的企业编号。
- 已有不同账号、已有密码或存在不一致的账号组合时，不混入默认密码；用户可以通过“填写当前页面”明确替换整组内容。
- 设置变更、页面切换或用户编辑发生在异步填写途中时，重新检查状态，避免用过期配置继续填密码。

## 界面

约 372px 宽的中文设置窗口，白色背景、深灰文字和克制红色主按钮。字段具备标签、密码显隐、键盘焦点和就地错误反馈。页面说明仅陈述本地保存方式，不嵌入网站实现细节。

## 验证与交付

- 校验清单文件与 JavaScript 语法，测试 URL 限定、本地配置行为、手动填充消息来源与异步编辑保护。
- 在真实 Chromium 中测试页面延迟加载、密码掩码、切换登录方式、用户编辑保护、手动覆盖和关闭自动填写。
- 使用虚构测试数据，不执行登录或发送验证码。
- 交付可“加载已解压的扩展程序”的 extension 文件夹、ZIP 和中文安装说明。
